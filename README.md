# hh-assistant — ассистент откликов на hh.ru (вариант A: полуавтомат)

Приложение собирает вакансии, оценивает релевантность (ИИ), готовит персональное сопроводительное письмо и ведёт очередь откликов. **Отправку выполняет человек** — приложение даёт карточку «открыть вакансию → письмо в буфере», что исключает риск блокировки аккаунта.

Репозиторий: https://github.com/Ollegro/hh-assistant

## Что уже работает в MVP

| Модуль | Функция |
|---|---|
| `hhassist/collector.py` | поиск вакансий на hh.ru (HTML-страницы поиска + карточки вакансий), нормализация полей; `collect()` — единая точка входа с выбором источника |
| `hhassist/hh_api.py` | клиент api.hh.ru: токен приложения (`/token`, `client_credentials`), Bearer-запросы, gzip, ETag/304, повторы на 429/5xx, `HHApiError` с `request_id` |
| `hhassist/api_adapter.py` | JSON API → та же модель вакансии, что у HTML-парсера (`source="api"`) |
| `hhassist/matching.py` | сопоставление вакансии с резюме: целевые роли, стек (must/nice), уровень, стоп-листы, поисковые запросы |
| `hhassist/storage.py` | SQLite: вакансии, письма, журнал откликов и статусов, события |
| `hhassist/scoring.py` | скоринг 0–100: правила по резюме (роль, стек, уровень, зарплата, формат, опыт, стоп-слова) + LLM (если задан ключ) |
| `hhassist/letters.py` | генерация письма: LLM (few-shot по вашим письмам) или офлайн-сборка из проверенных блоков |
| `hhassist/queue.py` | очередь откликов, дедупликация, дневной лимит, смена статусов, экспорт письма в .txt |
| `hhassist/jobs.py` | пакетные действия (сбор по всем запросам, оценка новых, письма, экспорт) — один код для CLI и веб-интерфейса, одна транзакция на прогон |
| `hhassist/analytics.py` | воронка (найдено → оценено → письмо → отправлено → ответ), конверсии, разрезы по баллам/форматам/компаниям, CSV-выгрузка |
| `hhassist/web.py` | локальный веб-интерфейс: список вакансий, оценка, письмо, статусы отклика, страница «Воронка» |
| `cli.py` | команды: `collect` (`--source auto/api/html`), `score`, `letters`, `serve`, `export` (`--csv`), `funnel`, `mark`, `stats`, `api-check` |

## Как этим пользоваться (два режима)

### 1. Основной: браузер, без консоли

Двойной клик по файлу **`Запустить hh-assistant.bat`** в этой папке:
- откроется окно сервера (свёрнутое) и браузер на `http://127.0.0.1:8765`;
- на странице сверху кнопки: **Собрать вакансии** · **Оценить** · **Сгенерировать письма** · **Экспорт писем в файлы**;
- в таблице — вакансии с баллами, кнопка **открыть** ведёт в карточку;
- в карточке: ссылка «Открыть вакансию на hh» (в новой вкладке), текст письма, кнопки **Скопировать письмо**, **Отметить отправленным**, **Пропустить**, **Скачать .txt**, а также статусы ответа — **Ответили**, **Приглашение**, **Отказ**;
- кнопка **Воронка и ответы** — найденное → оценённое → письма → отклики → ответы, конверсии, разрезы по баллам/форматам/компаниям и список откликов без ответа.

Цикл одного отклика: открыть карточку → «Открыть вакансию на hh» → на hh нажать «Откликнуться» → вставить письмо → вернуться в ассистент → «Отметить отправленным». Счётчик дня и остаток лимита видны в шапке.

**Сколько вакансий собирается за клик.** «Собрать вакансии» проходит по всем запросам из
`config/queries.txt` (5 запросов — 5 поисков) и на каждый запрос скачивает до `COLLECT_LIMIT`
вакансий с `COLLECT_PAGES` страниц выдачи. Значения по умолчанию — 20 вакансий и 1 страница,
то есть до 100 вакансий за клик; «широкий» сбор `COLLECT_LIMIT=25`, `COLLECT_PAGES=2` даёт
до 125. Внизу страницы появляется отчёт вида
«собрано вакансий: 93 из 1200 найденных (источник: html, запросов: 5, лимит: 20)»:
первое число — сколько скачано и сохранено, второе — сколько всего нашёл поиск.

**«Оценить» считает только новые вакансии** (те, у которых ещё нет оценки), поэтому повторный
клик не тратит время и токены LLM. Полная переоценка после правки профиля —
`python tools/run_hh_assistant.py score --all`.

### 2. Дополнительный: командная строка (для пакетных прогонов)

Все команды выполняются из папки приложения — напрямую или через обёртку `tools/run_hh_assistant.py`
(она просто делает `chdir` в папку приложения и запускает `cli.py`):

```bash
cd APPLICATION-hh-assistant        # папка приложения = корень репозитория
python cli.py stats                # то же: python tools/run_hh_assistant.py stats
python tools/run_hh_assistant.py collect --query-file config/queries.txt --pages 1 --limit 5
python tools/run_hh_assistant.py collect --query "AI инженер" --source api --limit 5  # только API
python tools/run_hh_assistant.py api-check   # проверка токена hh и доступа к API
python tools/run_hh_assistant.py list
python tools/run_hh_assistant.py score
python tools/run_hh_assistant.py letters --threshold 55
python tools/run_hh_assistant.py export       # письма в out/
python tools/run_hh_assistant.py export --csv # таблица вакансий out/vacancies.csv (Excel: «;», utf-8-sig)
python tools/run_hh_assistant.py funnel       # воронка откликов и конверсии (--days 30 — окно ожидания)
python tools/run_hh_assistant.py mark 12345 --status приглашение --note "созвон 27.10"
python tools/run_hh_assistant.py serve        # http://127.0.0.1:8765
python tools/run_hh_assistant.py reset --yes  # очистить базу и собрать заново
```

Русские поисковые запросы удобно держать в `config/queries.txt` (по одному в строке) и передавать через `--query-file`.

### Воронка откликов, статусы и CSV

Отклик проходит статусы: `отправлено вручную` → `ответ` → `приглашение` / `отказ`;
`пропущено` — сознательный отказ от вакансии. Каждая смена статуса — отдельная запись
журнала `applications`, поэтому история не теряется, а текущий статус вакансии — последняя запись.

- в карточке вакансии: кнопки **Ответили**, **Приглашение**, **Отказ** (и прежние **Отметить отправленным** / **Пропустить**);
- в консоли: `python cli.py mark <id> --status ответ|приглашение|отказ|sent|skip`;
- отчёт: `python cli.py funnel` — шаги воронки с конверсиями, «готово к отправке», «пропущено», «без ответа > N дн.», приглашения, отказы;
- окно ожидания ответа задаётся `REPLY_WAIT_DAYS` в `.env` (по умолчанию 14 дней);
- в браузере: страница **`/funnel`** — те же цифры плюс разрезы «балл → ответы», «формат работы», «компании», список ответов работодателей и список откликов без ответа.

Выгрузка таблицы: `python cli.py export --csv` → `out/vacancies.csv` (разделитель `;`,
кодировка utf-8-sig — открывается в Excel двойным кликом): id, балл, вердикт, вакансия,
компания, формат, опыт, зарплата, ссылка, длина письма, текущий статус, дата, примечание.

Зависимости: только стандартная библиотека Python 3.10+ (без pip install). LLM-функции включаются, если в `.env` заданы `LLM_PROVIDER` (openai, openrouter, deepseek, ollama, yandex), `LLM_MODEL` и `LLM_API_KEY`; `LLM_BASE_URL` нужен только для своего шлюза. Без ключа работает офлайн-режим.

## Источник данных: API hh.ru или HTML-парсер

Источник выбирает `HH_SOURCE` в `.env`:

| Значение | Поведение |
|---|---|
| `auto` (по умолчанию) | если настроен токен приложения hh — API; если токена нет или API ответил ошибкой — HTML-парсер, а причина отката пишется в журнал `events` |
| `api` | только API: ошибка не скрывается, отката нет |
| `html` | только HTML-парсер (токен не нужен) |

**Про токен честно.** 15.12.2025 hh.ru прекратил поддержку API для соискателей, а форма
заявки на dev.hh.ru предлагает только варианты «сотрудники работодателя» — то есть
личному ассистенту токен может не достаться вовсе. Это не блокер: без токена приложение
работает полностью, через HTML-парсер, и `HH_SOURCE=auto` сам выберет этот путь.

**Сценарий «ИП / кадровое агентство».** По п.1.2 Условий API учётную запись на hh.ru получают
в том числе «кадровые агентства и частные рекрутеры», поэтому заявка под ИП-агентство возможна
и легальна. Но п.1.5 разрешает таким пользователям применять Сервис «только для целей
привлечения потенциальных работников и их последующего трудоустройства», а п.1.6 даёт hh право
отказать при иных целях. Значит токен от агентской заявки нельзя использовать как личный
ассистент соискателя: личный поиск работы остаётся на HTML-парсере, агентские задачи (подбор
для клиентов) — отдельный сценарий на API. Подробный разбор с цитатами и чек-листом —
`../01_Разбор_API_hh.md` §7.

Если токен появился (заявку одобрили или есть доступ работодателя):

```bash
# .env — либо готовый токен из кабинета dev.hh.ru/admin, либо пара для авто-запроса
HH_APP_TOKEN=<токен из кабинета>
# HH_CLIENT_ID=<client_id>
# HH_CLIENT_SECRET=<client_secret>
HH_SOURCE=auto
```

Проверка (значения токена и секрета не печатаются):

```bash
python cli.py api-check        # в обёртке: python tools/run_hh_assistant.py api-check
python tools/hh_api_token.py   # тот же отчёт в out/hh-api-check.txt
```

Проверяется цепочка «токен → `GET /me` → `GET /vacancies?text=python&per_page=1`».
При ошибке печатаются HTTP-код, `value` (`bad_authorization`, `forbidden`, …) и `request_id` —
его указывают в обращении на api@hh.ru.

Как устроен клиент (`hhassist/hh_api.py`):

- токен приложения: `POST https://api.hh.ru/token`, тело `application/x-www-form-urlencoded`,
  `grant_type=client_credentials`; срок не ограничен, `refresh_token` не выдаётся,
  повторная генерация отзывает предыдущий токен — поэтому `HH_APP_TOKEN` приоритетнее пары
  `HH_CLIENT_ID`/`HH_CLIENT_SECRET`;
- запросы: `Authorization: Bearer <токен>`, обязательный `User-Agent`, gzip,
  ETag/`304 Not Modified`, повторы на `429/5xx` с учётом `Retry-After`, на `401/403` повторов нет;
- глубина выдачи hh — `page * per_page ≤ 2000`, `per_page ≤ 100`: проверяется до запроса;
- тексты ошибок и записи в `events` не содержат ни токена, ни `client_secret`.

## Как приложение учитывает резюме

Профиль `config/profile.json` — это ваше резюме в машинном виде: профессия, целевые роли, уровень,
история работы (компания, должность, период, домен), стек технологий (`must` / `nice` / `avoid_in_title`),
образование, языки, локация, вилка, стоп-лист компаний, белый список фактов и честные пробелы.
Шаблон — `config/profile.example.json`; личный профиль исключён из публикации через `.gitignore`.

| Правило | Вклад в балл |
|---|---|
| целевая роль найдена в заголовке | +20 |
| нецелевой стек в заголовке (`avoid_in_title`) | −25 |
| стек `must` (4 балла за термин) и `nice` (1,5), не выше 25 | 0…+25 |
| ни одного совпадения по стеку | −15 |
| уровень ниже целевого (junior / стажёр / нет опыта) | −20 |
| уровень выше целевого (руководитель / head / CTO) | −10 |
| стоп-слово профиля | −35 |
| зарплата ниже вилки / в вилке | −30 / +10 |
| формат работы вне предпочтений / в предпочтениях | −10 / +8 |
| опыт 1–3 года / требуется 6+ лет | +6 / −12 |
| компания в стоп-листе профиля | балл 0, вердикт «не откликаться» |

Поисковые запросы собираются из целевых ролей профиля (`matching.build_queries`),
а файл `config/queries.txt` при наличии переопределяет их вручную.
В карточке вакансии есть блок **«Сопоставление с профилем»**: что совпало, а чего в тексте вакансии нет.

## Как включить LLM (скоринг и письма)

Быстрая проверка без консоли: двойной клик по файлу **`Проверить LLM.bat`** — он по очереди
запускает `tools/check_llm.py` (настройки → связь → скоринг → письмо) и
`tools/compare_scores.py --limit 15` (правила против модели) и не закрывает окно с результатом.
Отчёты дублируются в файлы `out/llm-check.txt` и `out/score-compare.txt` — их удобно
приложить при разборе ошибки. Второй bat, **`Запустить тесты.bat`**, прогоняет
`unittest` (143 теста), `tools/check_hh_server.py`, `tools/check_serve.py` и `stats`, отчёт — `out/regress.txt`.

По умолчанию приложение работает офлайн: балл считают правила, письмо собирается из проверенных
блоков. LLM подключается несколькими строками в `.env` (шаблон — `.env.example`):

| Провайдер | `LLM_PROVIDER` | `LLM_MODEL` (пример) |
|---|---|---|
| OpenAI | `openai` | `gpt-4o-mini` |
| OpenRouter | `openrouter` | `anthropic/claude-3.5-sonnet` |
| DeepSeek | `deepseek` | `deepseek-chat` |
| Ollama (локально) | `ollama` | `llama3.1` (ключ — любая непустая строка) |
| Yandex Cloud | `yandex` | id модели; `LLM_BASE_URL` берётся из консоли |

`LLM_BASE_URL` заполняется только для своего или корпоративного шлюза. Проверка контура одной командой:

```bash
python tools/check_llm.py     # настройки → связь с моделью → скоринг тестовой вакансии → письмо
```

Что меняется при включённом LLM:

- итоговый балл = `0.45 × правила + 0.55 × LLM`, в причинах появляется «фокус» для письма;
- письмо пишет модель (few-shot по вашим образцам), проверка длины и формата остаётся;
- при сбое сети, лимите или неверном ключе приложение **не падает**: оценка и письмо откатываются
  к офлайн-режиму, а причина видна в причинах балла («LLM недоступен: …»);
- ключ нигде не печатается: в интерфейсе и консоли видно только «задан / не задан»;
- режим виден в шапке веб-интерфейса и в `stats` (`LLM: модель @ адрес` или «офлайн-режим»).

## Безопасность и правила

1. Отклики отправляет человек: приложение не автоматизирует отправку (нет риска блокировки).
2. Дневной лимит в конфиге — по умолчанию 200 откликов (столько же разрешает hh.ru); при массовых однотипных откликах площадка ограничивает аккаунт, поэтому на практике полезнее 30–50 точных откликов в день.
3. Письмо готовится под каждую вакансию; одинаковые письма блокируются.
4. Дедупликация: одна вакансия — один отклик (hh не принимает повторный отклик).
5. Соблюдается `User-Agent` в формате `App/1.0 (email)` — требование API hh.

## Ограничения (честно)

- Отклик через API hh недоступен (закрыт 15.12.2025) — приложение только готовит данные.
- Поиск вакансий идёт по HTML-страницам hh.ru (основной путь) либо через API, если есть токен приложения; при смене вёрстки или API потребуется правка адаптера (`collector.py` / `api_adapter.py`).
- LLM-скоринг и генерация писем требуют ключа API; без него работает офлайн-режим (правила + шаблонные блоки).

## Структура проекта

```
APPLICATION-hh-assistant/     # приложение (stdlib-only) — корень репозитория
  cli.py                      # команды: collect, score, letters, serve, export (--csv), funnel, mark, list, stats, reset
  hhassist/                   # модули: collector, hh_api, api_adapter, matching, scoring, letters,
                              #          storage, queue, analytics, jobs (пакетные действия), web, config, llm
  config/                     # profile.json (личный, в .gitignore), profile.example.json, queries.txt
  data/, out/                 # база SQLite, выгруженные письма и CSV (в .gitignore)
  tests/                      # 143 юнит-теста (unittest, stdlib) + fixtures/
  tools/                      # лаунчер, проверки (сервер, serve, LLM, парсер, токен, скоринг)
  PLAN.md, DEVLOG.md, README.md, LICENSE, .gitignore
  Запустить hh-assistant.bat  # запуск веб-интерфейса в один клик
  Проверить LLM.bat           # tools/check_llm.py + tools/compare_scores.py в одном окне
  Запустить тесты.bat         # unittest + проверки сервера + stats, отчёт в out/regress.txt
```

## Тесты

```bash
cd APPLICATION-hh-assistant
python -m unittest discover -s tests -v   # 143 теста, без сети и без зависимостей
```

Проверяются: HTML-парсер на сохранённой фикстуре, сопоставление с профилем (`matching`),
скоринг и вердикты, генерация и валидация письма, LLM-контур (провайдеры, повторы после 429,
откат к правилам, разбор JSON, отсутствие утечки ключа), API-источник (`hh_api`, `api_adapter`,
откат `auto`→HTML), формула итогового балла `scoring.combine_scores`, пакетные действия
`jobs` (оценка только новых, письма по порогу, один коммит на прогон, ошибка одного запроса
не рушит сбор), воронка и статусы отклика (`analytics`: шаги и конверсии без деления на ноль,
окно «нет ответа», разрезы по баллам/форматам/компаниям, CSV с BOM и `;`,
история журнала и текущий статус), страницы `/funnel` и кнопки статусов в карточке.
