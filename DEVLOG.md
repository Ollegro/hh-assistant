**Задача.** Нужно уметь прервать ошибочно запущенный прогон (случай: по ошибке запущен сбор
«Водитель» по всей России).

**Что сделано сразу.** Прогон на сервере остановлен перезапуском сервиса
(`systemctl restart hh-assistant`) — фоновый поток умирает вместе с процессом. По журналу
событий прогон успел завершиться сам (событие `collect` id 55, 16:37), в базе осталось
50 вакансий: 10 по Алтайскому краю и 40 «Водитель» из других регионов.

**Сделано в коде.**
- `RUN["stop"]` — флаг остановки; `start_action` сбрасывает его при запуске и передаёт в
  фоновый поток как `should_stop`.
- `jobs.collect_queries` / `score_pending` / `make_letters` принимают `should_stop` и проверяют
  флаг между карточками и запросами. Сбор пишет в примечаниях «остановлено пользователем:
  сохранено N из M найденных», оценка и письма — «· остановлено пользователем».
- `POST /run/stop` + красная кнопка «Остановить <действие>» на главной, видна только во время
  прогона; после нажатия блокируется, а плашка показывает «останавливаю…».
- Текущая карточка доскачивается, дальше прогон выходит; **уже сохранённое остаётся в базе**
  (об этом подпись рядом с кнопкой).

**Проверено.** 345 тестов OK (+5: остановка сбора после первого запроса, наличие кнопки только
во время прогона, `stop_run` и повторный вызов, блокировка кнопки, ответ без прогона).
Скриншот страницы во время прогона. На сервере после выкладки коммита `eeba776`: кнопка

**Симптом.** После очистки базы, сохранения 5 запросов и выбора «Алтайский край» нажата
«Собрать вакансии» — селект вернулся к «вся Россия», и сбор пошёл по всей стране.

**Диагноз.** Кнопки действий жили внутри GET-формы селекта и полагались на
`formmethod='post'` + `formaction`. Если регион в POST не попадал (браузер не учёл подмену
метода или клик случился до перезагрузки после смены региона), `_post` получал пустое
значение и **молча подставлял 113**: сбор шёл по России, в отчёте «регион: Россия», селект
возвращался к «вся Россия». Подтверждение по боевой базе: событие `collect` id 48 —
`area='Россия'`, `saved=171`, `found=211`, в вакансиях Москва/Санкт-Петербург/Свердловская.
Отдельно проверил старую разметку настоящим браузером (headless Edge, страница с того же
origin): с `formmethod` регион 1217 доезжал — значит баг плавающий (браузер/тайминг), и
полагаться на подмену метода нельзя.

**Исправление.**
- `web.render_index`: селект остаётся в GET-форме (`.region-form`, `onchange` → перезагрузка),
  кнопки действий — отдельные POST-формы (`form.action-form`) с hidden-полями `region`
  (значение из рендера) и `f_*` (фильтры). `formmethod` больше не используется.
- `REGION_SYNC_JS`: перед отправкой формы действия hidden `region` переписывается из селекта —
  закрывает сценарий «сменил регион и сразу нажал, не дождавшись перезагрузки».
- `_post`: если для сбора регион не пришёл — **сбор не запускается**, в сообщении просьба
  выбрать регион (раньше молча бралась вся Россия).
- Сообщение о запуске содержит регион: «запущено: сбор вакансий — страница обновится сама ·
  регион: Алтайский край».

**Проверено.** 323 теста OK (+4: hidden-регион в POST-форме, фильтры в форме, отказ без
региона, имя региона в сообщении); живой браузер (headless Edge, same-origin) — клик по
«Собрать вакансии» при выбранном Алтае даёт `area='1217'` даже без перезагрузки страницы;

**Следующий шаг:** выложить на сервер, очистить базу и собрать заново по «Алтайскому краю».

## 28.10.2026 — время последнего сбора по Москве, плашка прогона в шапке, баланс DeepSeek

**Задача.** На главной должно быть видно время последнего сбора вакансий; в шапке, на самом
верху — сообщение о запуске действия; в углу страницы — остаток на счёте DeepSeek.

**Исследование (часовой пояс).** `storage.now()` = `datetime.now()` без зоны, то есть время
машины, где идёт процесс. Домашний ПК — `Russian Standard Time` (UTC+03:00, проверено
`tzutil /g` и `datetime.now().astimezone()`), сервер Selectel — `Etc/UTC` (`timedatectl`,
в `deploy/hh-assistant.service` переменная `TZ` не задана). Боевая база: событие `collect`
id 43 — `2026-10-28T03:11:43`, 68 вакансий, то есть сбор был в **06:11:43 МСК**. Времени на
странице не было вообще: плашка «последний прогон — …» печатает только текст отчёта, а `RUN`
живёт в памяти и после перезапуска сервера пуст.

`MAX(COALESCE(seen_at, created_at))`, если журнал очищен кнопкой «Очистить базу».

**Сделано.**
- `hhassist/storage.py`: `moscow_tz()` (`zoneinfo`, при отсутствии базы зон — фикс. +03:00),

  209 найденных» под кнопками; сообщение о действии перенесено из карточки в шапку

**Список: один запрос вместо подзапроса на строку.** В `queue.next_batch` счётчик откликов

## 23.10.2026 (этап 7) — вход по паролю, HTTPS и размещение на сервере

   `suspect` — если у большинства вакансий пустой заголовок или описание короче 100 символов
   (порог — минимум 3 совпадения и больше половины пачки, чтобы одиночные результаты не пугали).
   При `suspect/empty` пишется событие `parser_suspect`, на главной сутки висит баннер.
5. **Регионы.** `COLLECT_AREAS` (по умолчанию `113` — вся Россия) — id через запятую или имена
   (`moscow`, `spb`, `rf`); `area` уходит в поиск повторяющимся параметром
   (`urlencode(..., doseq=True)`), для API и HTML одинаково. Регион вакансии парсится
   (`area`, `area_id`: JSON-блок у API/HTML), хранится в `vacancies` и показывается фильтром
   на главной (список городов берётся из самой базы — без отдельного справочника регионов).
   Плюс `COLLECT_REMOTE`/`--remote` — только удалёнка.

**Проблема:** старые базы не имеют новых колонок, а система миграций в проекте отсутствовала.
**Как решено:** `storage._migrate()` — аддитивные `ALTER TABLE` по `PRAGMA table_info`,
с бэкфиллом `seen_at = created_at`; пишет только когда колонки действительно не хватает
(иначе каждый `connect()` открывал бы транзакцию и мешал соседним соединениям — поймано тестом
на «upsert без commit»).

**Тесты:** `tests/test_improvements.py` — 26 новых (миграции, правка письма, кулдаун, инкремент,
health-check, регионы), всего **169**, все зелёные.

## 23.10.2026 (вечер): сбор по всей выдаче, честные числа в отчёте

**Проблема:** кнопка «Собрать вакансии» брала только первые 3 запроса и по 5 вакансий
(числа были зашиты в `web.run_action`) — при пяти запросах в `config/queries.txt` часть
не использовалась, а «Оценить» каждый раз пересчитывала все вакансии заново, тратя время
и токены LLM.

**Как решено:**
- `config.py` — поля `Settings.collect_limit` (20), `collect_pages` (1),
  `collect_queries` (0 = все запросы) из `.env` (`COLLECT_LIMIT`, `COLLECT_PAGES`,
  `COLLECT_QUERIES`); `.env.example` дополнен блоком с примером «широкого» сбора.
- `web.run_action("collect")` — проходит по всем запросам из `config/queries.txt`
  (или первым `COLLECT_QUERIES`), на каждый запрос `pages=COLLECT_PAGES`,
  `limit=COLLECT_LIMIT`; ошибка одного запроса не прерывает остальные (попадает в отчёт
  и в `events` как `collect_error`), итог прогона пишется в `events` как `collect`.
  Отчёт: «собрано вакансий: N из M найденных (источник: …, запросов: …, лимит: …)».
- `collector.collect` — `info["found"]` теперь всегда «сколько нашёл поиск до лимита»,
  добавлено `info["taken"]` (сколько реально скачано) — одинаково для HTML- и API-пути;
  `cli collect` печатает оба числа.
- `web.run_action("score")` — только вакансии без оценки
  (`NOT IN (SELECT vacancy_id FROM scores)`), повторный клик даёт «оценено новых: 0»
  с подсказкой про `cli.py score --all` для полной переоценки после правки профиля.
- Тесты: новый `tests/test_web_actions.py` (13 тестов — все запросы, лимит/страницы/кап
  из настроек, ошибка запроса, пустой `queries.txt`, запись в БД, оценка только новых,
  чтение `COLLECT_*`) и два теста в `tests/test_hh_api.py` (`found` до лимита, `taken`
  для HTML и API). Временная SQLite и заглушка `collector.collect` — сеть и `data/` не нужны.

## 23.10.2026 (ночь): чистка проекта, один код для CLI и веба, подготовка репозитория

**Проблема:** логика сбора, оценки и писем была продублирована в `cli.py` и `hhassist/web.py`
(два почти одинаковых цикла), каждый `upsert_vacancy`/`save_score` делал собственный коммит
SQLite, а `tests/` и `tools/` лежали в родительской папке — папку приложения нельзя было
опубликовать как самостоятельный репозиторий.

**Как решено:**
- новый модуль `hhassist/jobs.py`: `collect_queries`, `score_pending`, `make_letters`,
  `export_letters`; CLI и веб-интерфейс вызывают один и тот же код, тексты отчётов сохранены;
- `hhassist/storage.py` — параметр `commit=True` у `upsert_vacancy`, `save_score`,
  `save_letter`, `add_application`, `log_event`; пакетные действия пишут одной транзакцией
  на прогон (было: коммит на каждую вакансию/оценку/письмо);
- убраны неиспользуемые импорты (`json`, `scoring`, `queue` в `web.py`; `json`, `queue`,
  `scoring` в `cli.py`);
- структура: `tests/` и `tools/` перенесены внутрь папки приложения — `tests/_bootstrap.py`
  больше не ищет приложение через `tools/hh_app_path.py`, корень вычисляется от папки тестов;

- в `tools/` приложения: `run_hh_assistant.py`, `check_serve.py`, `check_hh_server.py`,

  удалён устаревший `check_hh_web.py` — он ссылался на старое имя папки `hh-assistant`;
- удалён мусор: `__pycache__`, дубли папки `out/` в корне, временные отчёты проверок.
