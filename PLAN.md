# План проекта hh-assistant

Локальный ассистент поиска работы на hh.ru: собирает вакансии, оценивает их
релевантность под **конкретное резюме кандидата**, готовит персональное
сопроводительное письмо и ведёт очередь откликов. Отправку выполняет человек —
это осознанный выбор (вариант A, «полуавтомат»): нулевой риск блокировки аккаунта.

## 1. Цель и границы

**Цель:** сократить рутину поиска работы — от 2–3 часов ручного просмотра вакансий
до 10–15 минут проверки готовой очереди.

| Входит в проект | Не входит (сознательно) |
|---|---|
| Сбор вакансий с hh.ru (HTML-страницы поиска и карточек) | Автоматическая отправка откликов |
| Скоринг 0–100 под резюме кандидата (правила + LLM) | Обход капчи, эмуляция действий браузера |
| Генерация письма под вакансию (LLM + офлайн-сборка) | Хранение пароля от аккаунта hh |
| Очередь откликов, дневной лимит, дедупликация | Скрапинг чужих данных, продажа данных |
| Воронка откликов, конверсии, экспорт CSV | Автоматическая рассылка писем работодателям |
| Локальный веб-интерфейс и CLI | Работа без ведома владельца аккаунта |

## 2. Пользовательский сценарий (один отклик)

1. Двойной клик по `Запустить hh-assistant.bat` → браузер на `http://127.0.0.1:8765`.
2. Кнопки в шапке: **Собрать вакансии** (рядом — регион сбора и редактор поисковых запросов)
   → **Оценить**. Письма пакетно не генерируются: только кнопкой в карточке вакансии.
3. В таблице — вакансии выше порога с баллом и вердиктом; кнопка **Открыть** → карточка.
4. В карточке: **Скопировать письмо** → «Открыть вакансию на hh» → на hh нажать «Откликнуться» →
   вставить письмо → вернуться → **Отметить отправленным** или **Пропустить**.
5. Счётчики дня и остаток лимита видны в шапке; письма выгружаются кнопкой
   **Экспорт писем в файлы** (`.txt`, UTF-8 без BOM, CRLF).
6. Ответы работодателя приложение не отслеживает: API соискателя у hh закрыт,
   поэтому статусов «ответ / приглашение / отказ» и статистики по ним нет —
   приглашения и отказы смотрим на hh.ru в разделе «Отклики».

## 3. Архитектура

```
APPLICATION-hh-assistant/
├── cli.py                  # collect | score | letters | serve | export | mark | letter | list | stats | areas | reset
├── hhassist/
│   ├── config.py           # Settings (.env), профиль-резюме, пути, лимиты
│   ├── collector.py        # HTML-адаптер hh.ru: поиск + карточка + нормализация полей
│   ├── matching.py         # сопоставление вакансии с резюме: роли, стек, уровень, стоп-листы
│   ├── llm.py              # клиент LLM: провайдеры, повторы, разбор JSON, ошибки без секретов
│   ├── scoring.py          # правила (matching) + LLM-оценка, вердикт 0–100
│   ├── letters.py          # письмо: LLM few-shot по образцам или офлайн-сборка + валидация
│   ├── storage.py          # SQLite: vacancies, scores, letters, applications (журнал статусов), events
│   ├── queue.py            # очередь, дедупликация, дневной лимит, смена статусов, экспорт .txt
│   ├── analytics.py        # воронка, конверсии, разрезы по баллам/форматам/компаниям, CSV
│   └── web.py              # локальный веб-UI (http.server), кнопки действий, карточка, страница «Воронка»
├── config/profile.json     # резюме кандидата (в .gitignore), profile.example.json — шаблон
├── data/hhassist.sqlite3   # база (в .gitignore)
└── out/                    # выгруженные письма и CSV (в .gitignore)
```

Поток данных: `collector` → `storage.vacancies` → `matching` + `scoring` →
`storage.scores` → `letters` → `storage.letters` → `queue`/`web` → `storage.applications` →
`analytics.funnel` (цифры воронки и конверсии).

Зависимости: только стандартная библиотека Python 3.10+ (без `pip install`).
LLM включается переменными `.env`: `LLM_PROVIDER` (openai, openrouter, deepseek, ollama, yandex),
`LLM_MODEL`, `LLM_API_KEY`; `LLM_BASE_URL` нужен только для своего шлюза. Без ключа работает
офлайн-режим.

## 4. Учёт резюме при поиске и скоринге

Профиль (`config/profile.json`) описывает резюме: профессия, целевые роли, уровень,
история работы (компания/роль/период/домен), стек (`must`/`nice`/`avoid_in_title`),
образование, языки, локация, вилка, стоп-лист компаний, белый список фактов и честные пробелы.

| Правило (`matching.py`) | Вклад в балл |
|---|---|
| Целевая роль найдена в заголовке | +20 |
| Нецелевой стек в заголовке (`avoid_in_title`) | −25 |
| Стек `must` (по 4 балла) и `nice` (по 1,5), не выше 25 | 0…+25 |
| Ни одного совпадения по стеку | −15 |
| Уровень ниже целевого (junior/стажёр/нет опыта) | −20 |
| Уровень выше целевого (руководитель/head/CTO) | −10 |
| Стоп-слово из профиля | −35 |
| Зарплата ниже вилки / в вилке | −30 / +10 |
| Формат работы вне предпочтений / в предпочтениях | −10 / +8 |
| Опыт 1–3 года / требуется 6+ лет | +6 / −12 |
| Компания в стоп-листе профиля | балл 0, вердикт «не откликаться» |

Поисковые запросы формируются из `target_roles` и `queries` профиля
(`matching.build_queries`); файл `config/queries.txt` при наличии переопределяет их вручную,
а править его можно прямо на главной странице (блок «Поисковые запросы для сбора», `POST /queries`).

Если LLM настроен, итоговый балл считается функцией `scoring.combine_scores()`:
`0.45 × правила + 0.55 × LLM` (веса — константы `RULE_WEIGHT` / `LLM_WEIGHT`); в промпт передаётся
выжимка резюме (`matching.profile_brief`): роль, опыт, стек, образование, языки.
Расхождение двух оценок на реальных вакансиях показывает `python tools/compare_scores.py` —
по нему и решается, оставлять ли веса или сдвигать их в сторону правил либо модели.

## 7. Метрики

- Воронка: найдено → прошло скоринг → письмо готово → отправлено → ответ → приглашение.
- Конверсии по компаниям, форматам работы и диапазонам баллов.
- Средний балл отправленных откликов и доля ответов (ориентир отрасли ≈ 1 ответ на 18 откликов).
- Качество писем: доля писем, прошедших `validate_letter` без замечаний.

Все метрики считаются по локальной базе без сети: `python cli.py funnel` печатает воронку и
конверсии, страница `/funnel` показывает их же плюс разрезы и список «ждут ответа».
Статус отклика хранится в журнале `applications` (каждая смена — отдельная запись),
текущий статус — последняя запись вакансии; в аналитике используются коды
`sent` / `reply` / `invite` / `reject` / `skip`.

## 9. Безопасность

- Секреты только в `.env` (не коммитится): `LLM_API_KEY`, `HH_APP_TOKEN` и т.п.
- В публичный репозиторий попадают только `profile.example.json` и код.
- `User-Agent` в формате `App/1.0 (email)` — требование hh.ru.
- Локальный сервер по умолчанию слушает `127.0.0.1` и не выходит в сеть.
- Сеть: доступ к веб-интерфейсу только со входом (`WEB_AUTH_USER` / `WEB_AUTH_PASSWORD`,
  HTTP Basic — пароль запрашивает браузер) и по HTTPS (`WEB_TLS_CERT` / `WEB_TLS_KEY`).
  Если пароль не задан, сервер обслуживает только запросы с `127.0.0.1`, остальным отвечает
  `403`: случайный запуск с `--host 0.0.0.0` данные не откроет.
- Сервер: процесс под непривилегированным пользователем (`hhassist`), `ufw` пропускает только
  SSH и порт веб-UI, `.env` — `600`, `data/` и `out/` — `700`, systemd ограничивает запись
  каталогами приложения (`deploy/hh-assistant.service`).


## 10. 25.10.2026 — регион вакансии: город из блока `area` (утверждено)

**Проблема.** hh отдаёт у вакансии два разных места: `"area": {"@id": …, "name": "Донецк"}`
(регион самой вакансии) и `"address": {"city": "Московская область"}` (адрес работодателя).
Парсер берёт город из `addressLocality` и не читает блок `area` (регулярка ждала `"id"`,
а hh отдаёт `"@id"`), поэтому в списке вакансия из ДНР показывается с городом
«Московская область», хотя фильтр региона относит её к ДНР верно.

**План (утверждён 25.10.2026):**

1. `hhassist/collector.py`, `_area()`: читать блок `"area"` в обычном, HTML-экранированном
   (`&#34;`) и backslash-экранированном (`\"`) виде; заполнять `area_id`; город брать из
   `area.name`, `addressLocality` — запасной вариант, `region` — из `addressRegion`.
2. `tests/test_parser.py`: тесты на три формы блока `area` и на запасной путь без него.
3. `tools/refresh_areas.py` (`--dry-run/--all/--limit/--pause`): перекачать карточки и
   обновить `area`, `area_id`, `region` у старых строк; прогнать на сервере.
4. Проверка: все тесты, затем на сервере у вакансии `138437712` город должен стать «Донецк»,
   а фильтр ДНР её по-прежнему показывать.

**Критерии готовности:** тесты зелёные; в живой базе у вакансии `area_id` заполнен,
`area = Донецк`, `region = Донецкая Народная Республика`; на странице фильтра ДНР она
отображается с городом Донецк.

**Вне объёма:** менять принцип фильтрации по региону (он соответствует `area` hh) и
показывать адрес работодателя отдельной колонкой.

**Статус (25.10.2026): ✅ выполнено.** Парсер читает блок `area` (обычный, `&#34;` и `\"`),
`area_id` заполняется, город берётся из `area.name`; тесты — 266 OK. Коммит `34663f1`
выложен на сервер, `tools/refresh_areas.py` обновил 2 строки (`138437712`: «Московская
область» → «Донецк», `area_id=118`). Живая страница: фильтр ДНР (`region=2134`) — 2 строки,
у обеих город Донецк. Попутно обнаружено, что база была очищена кнопкой «Очистить базу»
в 07:26 (`reset`, `deleted: 2`) — восстановлена из бэкапа 06:24, пустая копия сохранена
как `/root/hh-backup/hhassist-empty-2026-10-25-0726.sqlite3`.

## 11. 25.10.2026 — домен `hh.jobsearch-ai.ru` (утверждено, выполнено)

**Цель.** Открывать приложение по HTTPS-домену с доверенным сертификатом, не трогая
остальные сайты на общем nginx; прямой доступ по IP:8443 закрыть.

**Шаги.** 1) A-запись `hh → 135.106.183.205` в зоне `jobsearch-ai.ru` (Selectel, панель —
API rrsets отдаёт 500/502). 2) nginx: 80 — ACME + 301, 443 — сертификат домена и прокси на
`https://127.0.0.1:8443` (`proxy_ssl_verify off`, HSTS, лимит на `/login`,
`client_max_body_size 10m`). 3) `certbot certonly --webroot … --cert-name hh.jobsearch-ai.ru`.
4) `install.sh --host 127.0.0.1`, `ufw delete allow 8443/tcp`. 5) Проверка: 301/303, вход,
cookie `Secure`, HSTS, чужие сайты живы.

**Критерии готовности.** `https://hh.jobsearch-ai.ru/` → 303 на `/login`, вход работает,
сертификат LE валиден, `http://` → 301, `https://<IP>:8443` снаружи недоступен,
`aicare24.ru` / `bot.` / `mail.` отвечают как раньше.

**Статус (25.10.2026): ✅ выполнено.** Сертификат до 2027-01-23; проверено: 301/303,
cookie `Secure/HttpOnly/SameSite=Strict`, главная 200 (2 строки), HSTS; чужие сайты
